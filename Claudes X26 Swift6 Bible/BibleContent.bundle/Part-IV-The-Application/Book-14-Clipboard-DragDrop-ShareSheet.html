IV.14  Book 14: Clipboard, Drag & Drop, Share Sheet

Claude's Xcode 26 Swift Bible -- Part IV: The Application

This chapter covers the three ways Apple platforms move data between places: the system clipboard on iOS and macOS, drag and drop between views and between apps, and the system share sheet for sending content to Messages, Mail, AirDrop, and other apps. The unifying protocol is Transferable, which a single type can adopt to participate in all three.

IV.14.1  Live Reference: Claudes LockBox + IntelligenceDemo

Claudes LockBox ships every pattern in this chapter at production scale. A tap on a photo thumbnail in a vault item's detail view opens a full-screen image viewer with a share button at the top — the system share sheet (UIActivityViewController wrapped via UIViewControllerRepresentable). Long-press on a photo presents a contextual menu with "View Full Size" or "Delete Page" options. Source: github.com/fluhartyml/Claudes-LockBox, specifically ImageViewerView.swift and ShareSheetView.swift. The full build walkthrough in Build-Along 03 covers the share-sheet integration; the architectural notes in Source Tour 18 (CryoTunes) cover where the same Transferable patterns get used inside a music app's now-playing surface. IntelligenceDemo shows the simplest end of clipboard support: the OCR-extracted text uses .textSelection(.enabled), which lets the system handle long-press / select-all / copy with no app code beyond that one modifier. No UIPasteboard calls, no custom menu — SwiftUI hands the selection and copy affordances to UIKit's standard text-selection UI. Source: github.com/fluhartyml/IntelligenceDemo.

IV.14.2  Transferable -- One Protocol Covers All Three

IV.14.2 ¶1 Transferable is the unifying protocol. A type that conforms to Transferable can be copied to the clipboard, dragged from one view to another, and handed to the share sheet -- all through the same API. If your data type conforms to Codable, the conformance is often a single line.

IV.14.2 ¶2
import CoreTransferable

struct Note: Codable, Transferable {
    let title: String
    let body: String

    static var transferRepresentation: some TransferRepresentation {
        CodableRepresentation(contentType: .json)
    }
}

IV.14.2 ¶3 CodableRepresentation is a built-in representation that encodes the type as JSON under the given Uniform Type Identifier (UTI). Now Note can cross every data-movement boundary SwiftUI understands.

IV.14.2 ¶4 For plain-text or image types you usually don't define a custom Transferable. String, URL, Data, Image, and UIImage / NSImage already conform.

IV.14.3  The Clipboard (Copy and Paste)

IV.14.3.1  Writing to the Clipboard

IV.14.3.1 ¶1 iOS uses UIPasteboard.general; macOS uses NSPasteboard.general. SwiftUI hides the platform split for simple cases with Button styles that target copying, but you'll often write directly.

IV.14.3.1 ¶2
#if os(iOS)
import UIKit

func copy(_ text: String) {
    UIPasteboard.general.string = text
}
#else
import AppKit

func copy(_ text: String) {
    NSPasteboard.general.clearContents()
    NSPasteboard.general.setString(text, forType: .string)
}
#endif

IV.14.3.1 ¶3 Plain text is the simplest case. Writing an image:

IV.14.3.1 ¶4
// iOS
UIPasteboard.general.image = UIImage(systemName: "heart")

IV.14.3.2  Reading from the Clipboard

IV.14.3.2 ¶1
#if os(iOS)
let text = UIPasteboard.general.string ?? ""
#else
let text = NSPasteboard.general.string(forType: .string) ?? ""
#endif

IV.14.3.3  Built-In Copy / Paste UI

IV.14.3.3 ¶1 On iOS, every TextField and TextEditor already shows a copy / paste menu when the user taps and holds. You don't wire that up. Where you DO wire it up is on non-text content -- a card view, an image tile -- via the .contextMenu:

IV.14.3.3 ¶2
Image("kitten")
    .contextMenu {
        Button {
            UIPasteboard.general.image = UIImage(named: "kitten")
        } label: {
            Label("Copy Image", systemImage: "doc.on.doc")
        }
    }

IV.14.4  Drag and Drop

IV.14.4.1  Making a View Draggable

IV.14.4.1 ¶1 Attach .draggable with a Transferable value:

IV.14.4.1 ¶2
struct Card: View {
    let note: Note

    var body: some View {
        Text(note.title)
            .padding()
            .background(.yellow)
            .draggable(note)
    }
}

IV.14.4.1 ¶3 That's it. On Mac the card now drags with a normal mouse. On iPad the user presses and lifts with a finger or Apple Pencil. The drag preview uses the view itself.

IV.14.4.1 ¶4 You can provide a custom preview:

IV.14.4.1 ¶5
Text(note.title)
    .draggable(note) {
        RoundedRectangle(cornerRadius: 8)
            .fill(.yellow)
            .frame(width: 80, height: 40)
            .overlay(Text(note.title).font(.caption))
    }

IV.14.4.2  Accepting a Drop

IV.14.4.2 ¶1 Attach .dropDestination to the view that should receive drops:

IV.14.4.2 ¶2
struct Trash: View {
    @State private var count = 0

    var body: some View {
        Image(systemName: "trash")
            .font(.largeTitle)
            .padding()
            .dropDestination(for: Note.self) { notes, _ in
                count += notes.count
                return true
            }
            .overlay(alignment: .topTrailing) {
                if count > 0 { Text("\(count)").padding(4).background(.red) }
            }
    }
}

IV.14.4.2 ¶3 The closure gets an array of the dropped values (multiple items can drop at once) plus a CGPoint location in the view's coordinates. Return true to accept the drop, false to refuse.

IV.14.4.3  Highlighting While Hovering

IV.14.4.3 ¶1 .dropDestination takes an isTargeted: binding that flips to true while something draggable is hovering over the view:

IV.14.4.3 ¶2
@State private var hovering = false

Image(systemName: "tray")
    .padding()
    .background(hovering ? .blue.opacity(0.2) : .clear)
    .dropDestination(for: Note.self) { notes, _ in
        return true
    } isTargeted: { hovering = $0 }

IV.14.4.4  Inter-App Drag on iPadOS

IV.14.4.4 ¶1 Because Transferable types also declare their UTI, a drag that leaves your app -- onto another app or into Files -- can still be accepted if the destination understands the UTI. Drag a note with .json type into Files and you get a .json file written there. Drag a plain String into Messages and it becomes a chat bubble. The system does the dispatch; you do nothing extra.

IV.14.5  The Share Sheet

IV.14.5 ¶1 The share sheet is the system UI for "send this content somewhere": Messages, Mail, AirDrop, Notes, copy, and any app that registered a share extension.

IV.14.5.1  SwiftUI's ShareLink

IV.14.5.1 ¶1 Most of the time you'll use ShareLink, which is to sharing what Button is to actions:

IV.14.5.1 ¶2
ShareLink(item: "Hello from the book") {
    Label("Share", systemImage: "square.and.arrow.up")
}

IV.14.5.1 ¶3 The label is optional; without one, ShareLink renders a default share glyph. ShareLink accepts any Transferable:

IV.14.5.1 ¶4
ShareLink(item: note,
          preview: SharePreview(note.title,
                                icon: Image(systemName: "note.text")))

IV.14.5.1 ¶5 SharePreview supplies the tiny preview that shows up at the top of the share sheet (the AirDrop card, the header in Messages, etc.).

IV.14.5.2  Multiple Items

IV.14.5.2 ¶1
let urls: [URL] = [photoOne, photoTwo, photoThree]
ShareLink(items: urls) { Label("Share Photos", systemImage: "photo") }

IV.14.5.3  Triggering the Share Sheet Manually (UIKit / AppKit)

IV.14.5.3 ¶1 Sometimes you want the share sheet to open in response to a custom gesture, not a button. Use UIActivityViewController on iOS:

IV.14.5.3 ¶2
#if os(iOS)
func share(_ items: [Any]) {
    guard let scene = UIApplication.shared.connectedScenes.first as? UIWindowScene,
          let root  = scene.windows.first?.rootViewController else { return }

    let vc = UIActivityViewController(activityItems: items, applicationActivities: nil)
    root.present(vc, animated: true)
}
#endif

IV.14.5.3 ¶3 On Mac, NSSharingServicePicker does the same job.

IV.14.6  Chapter Mini-Example -- Cards You Can Copy, Drag, or Share

IV.14.6 ¶1
import SwiftUI
import CoreTransferable

struct Note: Codable, Identifiable, Transferable {
    let id = UUID()
    var title: String
    var body: String

    static var transferRepresentation: some TransferRepresentation {
        CodableRepresentation(contentType: .json)
    }
}

struct CardBoard: View {
    @State private var notes: [Note] = [
        Note(title: "Milk", body: "2%, gallon"),
        Note(title: "Bread", body: "Sourdough"),
        Note(title: "Kale", body: "For the smoothie")
    ]

    var body: some View {
        ScrollView {
            VStack(spacing: 16) {
                ForEach(notes) { note in
                    NoteCard(note: note)
                }
            }
            .padding()
        }
    }
}

struct NoteCard: View {
    let note: Note
    @State private var hovering = false

    var body: some View {
        VStack(alignment: .leading) {
            Text(note.title).font(.headline)
            Text(note.body).font(.subheadline)
        }
        .padding()
        .frame(maxWidth: .infinity, alignment: .leading)
        .background(hovering ? .yellow.opacity(0.5) : .yellow.opacity(0.2))
        .cornerRadius(10)
        .contextMenu {
            Button("Copy Title") {
                #if os(iOS)
                UIPasteboard.general.string = note.title
                #else
                NSPasteboard.general.clearContents()
                NSPasteboard.general.setString(note.title, forType: .string)
                #endif
            }
            ShareLink(item: note,
                      preview: SharePreview(note.title,
                                            icon: Image(systemName: "note.text")))
        }
        .draggable(note)
        .dropDestination(for: Note.self) { incoming, _ in
            return true
        } isTargeted: { hovering = $0 }
    }
}

IV.14.6 ¶2 Each card can be copied from its context menu, dragged onto another card, and shared through the system share sheet. Users can also drag cards out to Files or Messages because Note carries a JSON UTI.
