III.9  Book 9: Text and TextField

III.9.1  Live Reference: QuickNote + Claudes LockBox

QuickNote uses TextField for the note title and TextEditor for the body, with the date picker, the photo grid, and the home-screen widget all hanging off that minimal text-input surface. Claudes LockBox uses TextField for the vault item title and PIN entry, with keyboardType: .numberPad on the PIN field and the standard alphanumeric keyboard on the title. The two sources side-by-side show the same chapter's API in two different production contexts. Sources: github.com/fluhartyml/QuickNote and github.com/fluhartyml/Claudes-LockBox. See Build-Along 02 (QuickNote) and Build-Along 03 (LockBox) for the build walkthroughs.

III.9.2  Text View Basics

III.9.2 ¶1 Text displays read-only strings in SwiftUI.

III.9.2 ¶2
Text("Hello, world")
Text(verbatim: "Hello, world") // skips localization lookup

III.9.2 ¶3 Use verbatim: when you have a string that should never be localized (user-generated content, codes, etc.).

III.9.2.1  String Interpolation

III.9.2.1 ¶1 Standard Swift interpolation works inside Text:

III.9.2.1 ¶2
Text("Score: \(score)")
Text("Price: \(price, format: .currency(code: "USD"))")
Text("Date: \(date, format: .dateTime.month().day())")
Text("Progress: \(value, format: .percent)")

III.9.2.1 ¶3 The format: parameter is the modern way. It handles localization automatically.

III.9.2.2  Markdown Support

III.9.2.2 ¶1 Text parses inline Markdown out of the box when you use a string literal:

III.9.2.2 ¶2
Text("This is **bold** and this is *italic*")
Text("Visit [Apple](https://apple.com)")
Text("Use `code` formatting")
Text("~~Strikethrough~~ text")

III.9.2.2 ¶3 Watch out: Markdown parsing only works with string literals or LocalizedStringKey. If you pass a String variable, it renders as plain text:

III.9.2.2 ¶4
let message = "This is **not bold**"
Text(message) // plain text, no markdown

// Fix: explicitly use LocalizedStringKey or AttributedString
Text(LocalizedStringKey(message)) // now it parses markdown

III.9.2.3  Concatenating Text Views

III.9.2.3 ¶1 You can combine Text views with +:

III.9.2.3 ¶2
Text("Name: ").bold() + Text(userName).foregroundStyle(.secondary)

III.9.2.3 ¶3 This is the only way to apply different styles to parts of the same line of text without using AttributedString.

III.9.3  Text Modifiers

III.9.3.1  Font

III.9.3.1 ¶1
Text("Title").font(.title)
Text("Body").font(.body)
Text("Caption").font(.caption)
Text("Custom").font(.system(size: 24, weight: .bold, design: .rounded))
Text("Custom").font(.system(.title, design: .monospaced))

III.9.3.1 ¶2 Built-in dynamic type sizes: .largeTitle, .title, .title2, .title3, .headline, .subheadline, .body, .callout, .footnote, .caption, .caption2.

III.9.3.1 ¶3 Always prefer dynamic type over fixed sizes. It respects the user's accessibility settings.

III.9.3.2  Color and Style

III.9.3.2 ¶1
Text("Styled").foregroundStyle(.primary)
Text("Tinted").foregroundStyle(.blue)
Text("Gradient").foregroundStyle(.linearGradient(
    colors: [.blue, .purple],
    startPoint: .leading,
    endPoint: .trailing
))

III.9.3.2 ¶2 foregroundStyle replaced foregroundColor (now deprecated). Use foregroundStyle.

III.9.3.3  Weight and Emphasis

III.9.3.3 ¶1
Text("Bold").bold()
Text("Italic").italic()
Text("Both").bold().italic()
Text("Light").fontWeight(.light)
Text("Heavy").fontWeight(.heavy)
Text("Wide").fontWidth(.expanded)

III.9.3.4  Spacing: Kerning vs Tracking

III.9.3.4 ¶1
Text("KERNING").kerning(2)   // adjusts space between character pairs
Text("TRACKING").tracking(2) // uniform spacing added to every character

III.9.3.4 ¶2 Practical difference: kerning respects ligatures and pair-specific adjustments. tracking is uniform. For most UI work, tracking is what you want. For body text, kerning is more typographically correct.

III.9.3.4 ¶3 Watch out: You cannot use both on the same Text. If you apply both, kerning is ignored.

III.9.3.5  Line Limits and Truncation

III.9.3.5 ¶1
Text("Long text here...")
    .lineLimit(2)
    .truncationMode(.tail) // .head, .middle, .tail

Text("Flexible")
    .lineLimit(1...5) // minimum 1 line, expand up to 5

III.9.3.6  Baseline and Spacing

III.9.3.6 ¶1
Text("Shifted").baselineOffset(5) // positive = up, negative = down
Text("Spaced").lineSpacing(8)     // extra space between lines

III.9.3.7  Text Case

III.9.3.7 ¶1
Text("hello").textCase(.uppercase) // "HELLO"
Text("HELLO").textCase(.lowercase) // "hello"
Text("hello").textCase(nil)        // no transformation

III.9.3.8  Selection

III.9.3.8 ¶1 Make text selectable by the user:

III.9.3.8 ¶2
Text("Copy this").textSelection(.enabled)

III.9.4  TextField

III.9.4 ¶1 TextField is for single-line text input.

III.9.4 ¶2
@State private var name = ""

TextField("Enter your name", text: $name)

III.9.4 ¶3 The first argument is the prompt/placeholder text.

III.9.4.1  Prompt Parameter

III.9.4.1 ¶1 For more control over the placeholder:

III.9.4.1 ¶2
TextField(text: $name, prompt: Text("Full name").foregroundStyle(.tertiary)) {
    Text("Name") // this is the label, used by accessibility
}

III.9.4.2  Axis Parameter (Expanding TextField)

III.9.4.2 ¶1 A TextField can expand vertically with the axis parameter:

III.9.4.2 ¶2
TextField("Write something", text: $bio, axis: .vertical)
    .lineLimit(3...6) // starts at 3 lines, grows to 6

III.9.4.2 ¶3 This gives you a text field that behaves like a growing text area. It starts compact and expands as the user types. Combine with lineLimit to control the range.

III.9.4.2 ¶4 Watch out: Without lineLimit, an axis: .vertical text field will grow without bound.

III.9.4.3  Keyboard Types

III.9.4.3 ¶1
TextField("Email", text: $email)
    .keyboardType(.emailAddress)

TextField("Phone", text: $phone)
    .keyboardType(.phonePad)

TextField("Number", text: $amount)
    .keyboardType(.decimalPad)

III.9.4.3 ¶2 Common types: .default, .asciiCapable, .numberPad, .decimalPad, .phonePad, .emailAddress, .URL, .webSearch.

III.9.4.4  Autocapitalization

III.9.4.4 ¶1
TextField("Name", text: $name)
    .textInputAutocapitalization(.words)

III.9.4.4 ¶2 Options: .never, .characters, .words, .sentences.

III.9.4.4 ¶3 Watch out: .textInputAutocapitalization replaced the old .autocapitalization modifier. Use the new one.

III.9.4.5  Autocorrection

III.9.4.5 ¶1
TextField("Username", text: $username)
    .autocorrectionDisabled(true)

III.9.4.6  Text Content Type

III.9.4.6 ¶1 Tells the system what kind of data this field collects, enabling autofill:

III.9.4.6 ¶2
TextField("Email", text: $email)
    .textContentType(.emailAddress)

TextField("Street", text: $street)
    .textContentType(.streetAddressLine1)

III.9.4.7  onSubmit

III.9.4.7 ¶1 Fires when the user taps Return:

III.9.4.7 ¶2
TextField("Search", text: $query)
    .onSubmit {
        performSearch()
    }

III.9.4.7 ¶3 You can also set the return key label:

III.9.4.7 ¶4
TextField("Search", text: $query)
    .submitLabel(.search) // .done, .go, .join, .next, .return, .search, .send
    .onSubmit { performSearch() }

III.9.4.8  Formatting Input

III.9.4.8 ¶1 Use format: for typed input that auto-formats:

III.9.4.8 ¶2
@State private var amount: Double = 0

TextField("Amount", value: $amount, format: .currency(code: "USD"))
TextField("Percent", value: $percent, format: .percent)
TextField("Count", value: $count, format: .number)

III.9.4.8 ¶3 Watch out: The binding updates only when the user commits (presses Return), not on every keystroke.

III.9.5  SecureField

III.9.5 ¶1 For password entry. Characters are hidden.

III.9.5 ¶2
@State private var password = ""

SecureField("Password", text: $password)
    .textContentType(.password)
    .onSubmit { authenticate() }

III.9.5 ¶3 SecureField supports the same modifiers as TextField: .onSubmit, .submitLabel, .textContentType, .textInputAutocapitalization, etc.

III.9.6  @FocusState

III.9.6 ¶1 Manage which field has keyboard focus programmatically.

III.9.6.1  Boolean Focus (Single Field)

III.9.6.1 ¶1
@FocusState private var isNameFocused: Bool

TextField("Name", text: $name)
    .focused($isNameFocused)

Button("Focus Name") {
    isNameFocused = true
}

III.9.6.2  Enum Focus (Multiple Fields)

III.9.6.2 ¶1
enum Field: Hashable {
    case firstName, lastName, email
}

@FocusState private var focusedField: Field?

Form {
    TextField("First", text: $first)
        .focused($focusedField, equals: .firstName)
        .onSubmit { focusedField = .lastName }

    TextField("Last", text: $last)
        .focused($focusedField, equals: .lastName)
        .onSubmit { focusedField = .email }

    TextField("Email", text: $email)
        .focused($focusedField, equals: .email)
        .onSubmit { submit() }
}
.onAppear { focusedField = .firstName }

III.9.6.2 ¶2 This creates a tab-through flow: Return moves focus to the next field.

III.9.6.3  Dismiss Keyboard

III.9.6.3 ¶1
// Set focus to nil to dismiss keyboard
focusedField = nil

III.9.6.3 ¶2 Watch out: @FocusState must be Optional when used with an enum (the nil state means nothing is focused). The boolean variant is non-optional.

III.9.6.3 ¶3 Watch out: Setting focus in onAppear can be unreliable on first launch. If you need guaranteed focus on appear, wrap it in a brief task delay:

III.9.6.3 ¶4
.task {
    try? await Task.sleep(for: .milliseconds(500))
    focusedField = .firstName
}

III.9.7  Common Patterns

III.9.7.1  Search Bar

III.9.7.1 ¶1
@State private var searchText = ""
@FocusState private var searchFocused: Bool

HStack {
    Image(systemName: "magnifyingglass")
        .foregroundStyle(.secondary)

    TextField("Search", text: $searchText)
        .focused($searchFocused)
        .onSubmit { runSearch() }
        .submitLabel(.search)

    if !searchText.isEmpty {
        Button {
            searchText = ""
            searchFocused = true
        } label: {
            Image(systemName: "xmark.circle.fill")
                .foregroundStyle(.secondary)
        }
        .buttonStyle(.plain)
    }
}
.padding(8)
.background(.quaternary, in: .rect(cornerRadius: 10))

III.9.7.2  Form with Validation

III.9.7.2 ¶1
@State private var email = ""
@FocusState private var emailFocused: Bool

var emailIsValid: Bool {
    email.contains("@") && email.contains(".")
}

TextField("Email", text: $email)
    .focused($emailFocused)
    .keyboardType(.emailAddress)
    .textContentType(.emailAddress)
    .textInputAutocapitalization(.never)
    .autocorrectionDisabled()
    .overlay(alignment: .trailing) {
        if !email.isEmpty && !emailFocused {
            Image(systemName: emailIsValid ? "checkmark.circle" : "exclamationmark.circle")
                .foregroundStyle(emailIsValid ? .green : .red)
                .padding(.trailing, 8)
        }
    }
