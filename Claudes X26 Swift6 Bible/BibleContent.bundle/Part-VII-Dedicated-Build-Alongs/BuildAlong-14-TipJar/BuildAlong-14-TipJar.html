Build-Along 14: TipJar

Distribution: GitHub clone-and-build. Single-concept teaching app — StoreKit 2 non-consumable in-app purchase (the tip jar pattern). Does not grow into a standalone product — a tip jar without an app context to tip FOR is inherently a demo. Shipping the source on GitHub for readers to clone is the honest path.

MVP concept: one screen with three tip tiers (small / medium / large), a StoreKit 2 purchase per tier, a thank-you confirmation, and a receipt. The whole point is showing StoreKit 2 end-to-end without any other distraction.

What TipJar will teach

  • StoreKit 2 — Product loading, purchase flow, transaction verification, receipt inspection, restore purchases. The modern async API set (not the StoreKit 1 delegate-based pattern).
  • Sandbox testing — App Store Connect sandbox accounts, StoreKit configuration files for local testing, purchase-state mocking.
  • Signature layer: MVP + Under the Hood + About & Send Feedback.
  • Distribution: GitHub clone-and-build.

Why GitHub clone-and-build not App Store (and why not folded into ReportMaker)

Two paths were considered: (a) fold TipJar into ReportMaker as an optional "support this app" tier, (b) keep it standalone. Folding dilutes ReportMaker's clean expense-tracker teaching surface and forces StoreKit into a teaching slot that wasn't supposed to be there. Standalone clone-and-build is cleaner — readers study StoreKit 2 in its purest form, ReportMaker stays focused on Swift Charts + PDFKit.
