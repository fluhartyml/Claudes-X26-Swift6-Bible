What Cryo Playlist Manager shows at production scale

  • Apple Music + Spotify cross-service playlist management — the only app in the family that talks to both services. Reads the user's playlists from each, lets the user copy / merge / sync between them.
  • M3U playlist import and export — the lingua franca of playlist exchange. M3U files are the closest thing to a portable playlist format; supporting them lets users move playlists across services and tools without lock-in.
  • iCloud Drive integration for playlist backups — using iCloud Drive's user-visible folder as a backup destination, separate from CloudKit's invisible-to-users data store. The user can see their backups in Finder.
  • OAuth2 flow for the Spotify side — demonstrates the modern macOS OAuth2 pattern (system browser sign-in with a custom URL scheme callback) that any app integrating a third-party service will need.
  • Sandboxed Mac App Store distribution while talking to two music services — the trick is that Spotify's web API is over plain HTTPS so it works inside the sandbox without entitlement gymnastics; Apple Music access via AppleScript needs the same temporary-exception entitlement Library Commander uses (Source Tour 22).

The Apple-Music-plus-Spotify shape

Most music apps pick one service. Cryo Playlist Manager intentionally bridges both, because users in the wild often have a foot in each ecosystem — Apple Music on their phone for car-play and Siri integration, Spotify on the desktop for the social and discovery features the family doesn't fight on. Moving playlists between the two is currently a manual chore that takes the user back to copy-pasting song titles into search bars.

The architecture in Services/ reflects that bridge:

  • PlaylistManager.swift — the orchestration layer that doesn't know about either service; it reasons about playlists in a service-agnostic data model
  • SpotifyAuthManager.swift + SpotifyService.swift — the Spotify-side adapter (OAuth2 + REST API)
  • PlaylistLockerService.swift — the lock-this-playlist-from-edits state, ported from Library Commander where the same pattern lives (cross-app code reuse worth flagging as a habit)
  • DislikeManager.swift — per-station dislike tracking, ported from CryoTunes Player

The DislikeManager and PlaylistLockerService ports are the lesson: when you build a family of apps that share patterns, port the proven implementations rather than rebuilding. Each port saves a debugging cycle and keeps behavior consistent across apps the user might use together.

The OAuth2-with-system-browser flow

Spotify (and most modern third-party APIs) requires OAuth2 sign-in. The recommended modern pattern uses the system browser, not an embedded web view inside the app:

  1. App opens the user's default browser with the Spotify authorization URL, including a custom URL scheme (e.g., cryoplaylistmanager://oauth-callback) as the redirect URI.
  2. User signs in to Spotify in the browser; Spotify redirects to the custom URL scheme with an auth code in the query string.
  3. macOS routes the custom URL back to Cryo Playlist Manager via the onOpenURL SwiftUI modifier.
  4. App exchanges the auth code for an access token via Spotify's token endpoint.
  5. Access token (and refresh token) are stored in Keychain.

The advantage over an embedded web view: the user signs in to Spotify in their normal browser session, where they're probably already signed in. They don't have to type a Spotify password into a third-party app. Apple has been steadily steering apps toward this pattern over the last few years; embedded web views for OAuth are flagged as a friction point in App Review for sandboxed Mac apps now.

The M3U interchange format

M3U files are plain text, one media file path per line, with optional metadata in #EXTINF comments. They're the universal "here's a playlist" file format — supported by VLC, iTunes (legacy), most Linux media players, every smart speaker app, and anything else that handles playlists. Cryo Playlist Manager imports and exports M3U as the bridge format between Apple Music and Spotify because both services have their own opaque playlist formats that don't interoperate.

The lesson worth flagging: when integrating with multiple services that don't share formats, find or define a lingua franca that both can be translated to and from. M3U was already standard; the app just adopted it. If you're integrating services that don't have a common format, defining one (even a trivial JSON shape) is preferable to writing N×N direct converters.
