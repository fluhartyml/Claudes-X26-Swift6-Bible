Source Tour 20: Snap & ScanKeeper

Status: LIVE on the App Store (v1.1). Production VisionKit document scanner with photo-library storage and folder organization.

Two paths: install the live app to use the finished product, or clone the repo and read the source. The architecture is small — ~820 lines across seven Swift files — so this is a good first source tour for a reader who wants to see a complete shipped app's full surface in one sitting. See Book 21 Git-And-GitHub for the clone workflow.

What Snap & ScanKeeper shows at production scale

  • The UIKit-to-SwiftUI bridge for system controllers — VisionKit's document scanner is delivered as a UIKit view controller, not a SwiftUI view. The wrapper pattern that brings it into a SwiftUI app is the same one you'd use for any system controller (camera picker, mail composer, document picker)
  • VisionKit document scanning via VNDocumentCameraViewController — full-screen, edge-detecting, perspective-correcting, multi-page-aware. Apple does the heavy lifting; the app just consumes the result
  • Photo library storage via PHPhotoLibrary with folder organization on top, instead of inventing a new storage layer
  • A complete, tightly-scoped utility app at ~820 lines — small enough to read end-to-end

The UIViewControllerRepresentable bridge

Apple ships some of its most powerful interactions as UIKit view controllers, not SwiftUI views. Document scanning is one of them. To use VNDocumentCameraViewController from a SwiftUI app, you wrap it in a UIViewControllerRepresentable. Open DocumentScannerView.swift — the whole bridge is 50 lines:

import SwiftUI
import VisionKit

struct DocumentScannerView: UIViewControllerRepresentable {
    @Environment(\.dismiss) private var dismiss
    let onScanComplete: (VNDocumentCameraScan) -> Void

    func makeUIViewController(context: Context) -> VNDocumentCameraViewController {
        let scanner = VNDocumentCameraViewController()
        scanner.delegate = context.coordinator
        return scanner
    }

    func updateUIViewController(_ uiViewController: VNDocumentCameraViewController, context: Context) {
        // No updates needed
    }

    func makeCoordinator() -> Coordinator {
        Coordinator(parent: self)
    }

    class Coordinator: NSObject, VNDocumentCameraViewControllerDelegate {
        let parent: DocumentScannerView

        init(parent: DocumentScannerView) {
            self.parent = parent
        }

        func documentCameraViewController(_ controller: VNDocumentCameraViewController, didFinishWith scan: VNDocumentCameraScan) {
            parent.onScanComplete(scan)
            parent.dismiss()
        }

        func documentCameraViewControllerDidCancel(_ controller: VNDocumentCameraViewController) {
            parent.dismiss()
        }

        func documentCameraViewController(_ controller: VNDocumentCameraViewController, didFailWithError error: Error) {
            print("Document scanner failed: \(error.localizedDescription)")
            parent.dismiss()
        }
    }
}

Three pieces, in order:

  • makeUIViewController returns the system controller, configured with a delegate. SwiftUI calls this once when the wrapper appears on screen.
  • Coordinator is a Swift class that conforms to whatever Cocoa-style delegate protocol the controller uses. Here it's VNDocumentCameraViewControllerDelegate; for a mail composer it'd be MFMailComposeViewControllerDelegate; for an image picker it'd be UIImagePickerControllerDelegate. The Coordinator translates UIKit-style delegate callbacks into SwiftUI-style closure invocations on the parent.
  • updateUIViewController handles state updates if the SwiftUI side changes. For a one-shot scanner like this one, it does nothing; for a controller whose configuration depends on SwiftUI state, this is where you'd push updates through.

The pattern generalizes. Anywhere Apple gives you a UIKit controller, this same three-piece bridge gets it into SwiftUI. UIImagePickerController for camera capture, MFMailComposeViewController for mail, UIDocumentPickerViewController for file picking, UIActivityViewController for share sheets — all the same shape.

Why VisionKit beats rolling your own scanner

VisionKit's VNDocumentCameraViewController handles, for free:

  • Full-screen camera preview with edge detection on the live feed
  • Perspective correction (you point the camera at a tilted document, the saved image is rectified)
  • Auto-capture when the document is well-framed
  • Multi-page batching (capture multiple pages, get them back as VNDocumentCameraScan.pageCount pages)
  • Color/grayscale/B&W filter selection in the post-capture review
  • Crop adjustment on each page

That's months of work if you build it from raw AVFoundation. VisionKit gives it to you in 50 lines of bridge code. The lesson: look for the system-provided controller before you build a custom one. Apple's first-party controllers tend to be polished, edge-case-aware, and accessibility-correct in ways that hand-rolled equivalents almost never are.
