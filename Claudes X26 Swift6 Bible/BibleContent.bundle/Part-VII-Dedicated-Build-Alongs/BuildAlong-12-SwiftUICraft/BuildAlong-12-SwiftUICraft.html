VII.12  Build-Along 12: SwiftUICraft

Distribution: GitHub clone-and-build — the black sheep of the roster. Every other build-along has a concrete user problem it solves. SwiftUICraft is the exception — it exists to teach three SwiftUI pattern concepts (custom ViewModifiers, @Observable macro, and List performance at scale) that don't coalesce into a single "real product" without stretching. It ships as a GitHub repo readers clone and build themselves because the honest framing is: this is a pattern playground, not a utility.

MVP concept: a single app that demonstrates three reusable SwiftUI patterns side by side — custom ViewModifier composition, @Observable macro state sharing across views, and a 10,000-row list with proper identity + lazy loading. Each pattern is demo-scale on purpose; the point is to show the craft technique, not ship a product.

VII.12.1  What SwiftUICraft will teach

VII.12.1 ¶1
  • Custom ViewModifiers — conforming to ViewModifier, composing modifiers, the extension View { func foo() pattern for ergonomic call sites, modifier ordering and how it affects layout.
  • @Observable macro — the modern replacement for ObservableObject. Class-based observable state, fine-grained tracking, avoiding the @StateObject/@ObservedObject/@EnvironmentObject confusion.
  • List performance — 10,000-row list with stable .id(), lazy rendering, per-row view complexity budget, .listRowSeparator tuning, .contentMargins for readable density.
  • Signature layer: MVP + Under the Hood + About & Send Feedback.
  • Distribution: GitHub clone-and-build.

VII.12.2  Why it's the black sheep

VII.12.2 ¶1 The other GitHub clone-and-build entries (TouchAndMove, DragBetweenWindows, CloudAndErrors, TipJar) teach cohesive single concepts. SwiftUICraft teaches three loosely related patterns in one app because putting each in its own app would inflate the roster. It's the compromise slot — "here's a corner of the book where we stack the SwiftUI idioms that don't fit anywhere else, and the app that demos them ships as a GitHub repo because it's honestly a pattern anthology, not a product."
